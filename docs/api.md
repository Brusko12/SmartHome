# API этапа 2

Адрес разработки: `http://127.0.0.1:8000`. Префикс прикладного API — `/api`.
OpenAPI доступен на `/openapi.json`, интерактивная документация — `/docs`.

## GET /api/health

Реальная проверка соединения с SQLite (`SELECT 1`) и текущей ревизии Alembic.

`200 OK`:

```json
{"status":"ok","version":"0.1.0","database":"ok"}
```

`503 Service Unavailable`, если база недоступна:

```json
{"status":"degraded","version":"0.1.0","database":"unavailable"}
```

`503 Service Unavailable`, если применённая ревизия отличается от ожидаемой:

```json
{"status":"degraded","version":"0.1.0","database":"migration_required"}
```

Ответы типизированы Pydantic и описаны в OpenAPI. Пути файлов и текст SQL-ошибки
не возвращаются клиенту. Ошибка соединения записывается в серверный журнал.
Если миграция не смогла примениться при старте, сервер не начинает работу.

Запросы с посторонним Host отклоняются с `400`, отсутствующие маршруты — с
`404`. Список разрешённых Host: `127.0.0.1`, `localhost`.

Endpoint публичный и не изменяет данные. Авторизация и защита изменяющих
запросов появятся на этапе 6. На этапе 2 все маршруты доступны локально без
сессии; наличие пользователя с хешем пароля не означает защиту API.

## Комнаты

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/rooms` | Пагинация, фильтр `home_id`, количество устройств |
| POST | `/api/rooms` | Создание комнаты, HTTP 201 |
| GET | `/api/rooms/{id}` | Комната с `device_count` |
| PATCH | `/api/rooms/{id}` | Название и/или иконка |
| DELETE | `/api/rooms/{id}` | Удаление пустой комнаты, HTTP 204 |

Создание: `{"home_id":1,"name":"Кабинет","icon":"house"}`. Имя обрезается
по краям, длина 1–200 символов. Имя уникально внутри дома. Иконка — имя из
латинских строчных букв, цифр и дефисов (до 64 символов).
PATCH не принимает пустой объект, null и неподдерживаемые поля.

Удаление непустой комнаты без переноса возвращает `409`. Можно указать
`?move_devices_to=<id>`: устройства сохраняют состояния и перемещаются в
другую комнату того же дома. Перенос, удаление и события атомарны.
Устройства никогда не уничтожаются вместе с комнатой.

## Устройства

| Метод | Путь | Результат |
|---|---|---|
| GET | `/api/devices` | Список с текущими состояниями |
| POST | `/api/devices` | Создание устройства и состояния, HTTP 201 |
| GET | `/api/devices/{id}` | Устройство и состояние |
| PATCH | `/api/devices/{id}` | Название, комната, параметры |
| DELETE | `/api/devices/{id}` | Удаление устройства и текущего состояния, HTTP 204 |
| GET | `/api/devices/{id}/state` | Актуальное сохранённое состояние |
| POST | `/api/devices/{id}/command` | Проверенная команда и новое сохранённое состояние |

Создание:

```json
{"room_id":1,"name":"Лампа","device_type":"light","parameters":{}}
```

Дом определяется по комнате. На этом этапе все новые устройства используют
`virtual`; выбрать MQTT или Home Assistant нельзя. Тип устройства после создания
не меняется. Перенос разрешён только между комнатами своего дома. Поле `parameters`
в PATCH заменяется целиком, отсутствующие значения получают дефолты типа.
Состояние напрямую через PATCH не меняется: только через команды.

Оба списка возвращают `{"items":[],"total":0,"limit":50,"offset":0}`.
`limit` от 1 до 100, `offset` неотрицательный, сортировка по ID.
Фильтры устройств: `home_id`, `room_id`, `device_type`.
Чтобы получить устройства комнаты, используйте `/api/devices?room_id=<id>`.

## Команды

Общая форма:

```json
{"command":"set_brightness","params":{"brightness":60}}
```

| Тип | Команда | params |
|---|---|---|
| light / outlet / tv | `turn_on`, `turn_off` | `{}` |
| light | `set_brightness` | `{"brightness":0..100}` — целое |
| light | `set_color` | `{"color":"#RRGGBB"}` |
| thermostat | `set_target_temperature` | `{"temperature":5..35}` °C |
| thermostat | `set_mode` | `{"mode":"Off"}`; также Heating, Cooling, Auto, Eco |
| motion_sensor | `simulate_motion`, `reset_motion` | `{}` |
| climate_sensor | `simulate_reading` | `{"temperature":-40..125,"humidity":0..100}` |
| tv | `set_volume` | `{"volume":0..100}` — целое |
| tv | `mute` | `{"muted":true}` или false |

Числа не принимаются в виде строк; логические параметры требуют true/false.
Лишние поля, неизвестные команды и команды другого типа возвращают `422`.
Неверная команда существующему устройству записывается в журнал как ошибка;
состояние и его время изменения остаются прежними. Ошибки HTTP-структуры
отклоняются до сервиса, без создания события устройства.

Изменение яркости, цвета, громкости и mute не переключает питание автоматически.
Для розетки `parameters.nominal_power_w` задаёт мощность включённого устройства
(больше 0, до 10 000 Вт, по умолчанию 60). При выключении мощность равна нулю.
`motion_sensor.parameters.reset_after_seconds`: 1–3600, по умолчанию 30.
Остальные типы сейчас принимают только пустой объект parameters.

Ответ состояния содержит `device_id`, `device_type`, типизированные `values`,
`source` и время `updated_at` в UTC. Ручные изменения датчиков имеют источник
`manual_simulation`, команды пользователя — `user`, изменение параметров —
`configuration`. Состояние и успешное событие сохраняются одной транзакцией.
Ошибка записи события откатывает изменение состояния.

## Граница этапа 2

Текущее управление работает по запросам. Фоновая симуляция — этап 5: температура
термостата пока не движется к цели, энергия розетки не накапливается, датчики сами
не обновляются, движение автоматически не сбрасывается. `reset_at` — сохранённый
срок для будущего симулятора; сейчас доступен явный `reset_motion`.

Журнал уже сохраняется в SQLite, включая снимок удалённого устройства и старое/
новое состояние команды. Маршруты просмотра истории — этап 6. Сценариев,
автоматизаций, расписаний, настройки через UI и системной диагностики пока нет.

## Ошибки

- `404`: объект не найден.
- `409`: дубликат комнаты, перенос между домами, удаление непустой комнаты
  без назначения либо нарушение связей.
- `422`: неправильные поля, параметры или неподдерживаемая команда.
- `503`: адаптер или хранилище недоступны.

Доменные ошибки: `{"detail":{"code":"conflict","message":"…"}}`.
Структурная валидация FastAPI использует стандартный массив `detail`.
Пути файлов, SQL и внутренние исключения не отправляются клиенту.
