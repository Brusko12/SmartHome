# Проверка этапа 1

Проверенная локальная среда: Linux, Python 3.12.14, Node.js 24.22.1,
Vite 7.3.8, системный Chromium через Playwright.

## Автоматические проверки

| Проверка | Результат |
|---|---|
| `python -m pytest backend/tests -q` | 45 тестов успешно |
| `ruff check backend` | Успешно |
| `ruff format --check backend` | Успешно |
| `python -m pip check` | Конфликтов зависимостей нет |
| `npm run build` | TypeScript и production-сборка успешны |

Backend-тесты проверяют:

- Первую миграцию всех девяти таблиц и отсутствие стандартных пользователей.
- Совпадение мигрированной схемы и ORM-метаданных.
- Применение миграций повторно без дублирования и потери данных.
- Сохранение состояния после закрытия engine и открытия базы заново.
- Повторный полный lifespan приложения с сохранением записей.
- Применение и откат начальной миграции на отдельной пустой тестовой базе.
- Связи всех моделей, уникальное текущее состояние устройства.
- Запрет удаления зависимых сущностей и привязок между разными домами.
- Каскадное удаление состояния и сохранение журнала при удалении устройства.
- Отсутствие повторного использования удалённого идентификатора устройства.
- Порядок действий, прямые действия расписания, ограничения времени/дней.
- Отбрасывание некорректных JSON, NaN, infinity и даты без часового пояса.
- Типы устройств, согласованность вида автоматизации и наличия триггера.
- Конфигурацию, абсолютные пути, UTF-8 `.env` и приоритет окружения.
- Настоящий `/api/health`, `503` при проблеме БД/ревизии, `404` и проверку Host.

Все тестовые базы изолированы от пользовательской SQLite.

## Запуск и браузер

Backend запущен командой `python -m app`, frontend — `npm run dev`.
Для проверки использовался отдельный постоянный каталог внутри рабочей среды,
переопределённый через `SMARTHOME_DATA_DIR`.

- Прямой запрос к `127.0.0.1:8000/api/health`: HTTP 200, БД `ok`.
- Запрос через Vite `127.0.0.1:5173/api/health`: тот же реальный ответ.
- Chromium показывает подключённую SQLite и версию backend.
- Проверены ширины окна 1280 и 360 пикселей; горизонтального переполнения нет.
- Смоделированы HTTP 503 и сетевой обрыв: страница показывает соответствующие
  состояния; повторная проверка после восстановления завершается успешно.
- Неизвестная страница показывает «Страница не найдена», ссылка возвращает домой.
- Ошибок JavaScript нет; внешних запросов страницы не зарегистрировано.

## Границы результата

В `.github/workflows/checks.yml` настроены backend-тесты на Ubuntu и Windows
и сборка frontend на Node.js 22. Наличие workflow само по себе не означает,
что его конкретный запуск уже прошёл: актуальный результат — во вкладке Actions.

Windows EXE не собирался и не проверялся: это этап 7. Чистая Windows,
запуск без среды разработки и финальная офлайн-проверка дистрибутива относятся
к этапам 7–8. Браузерная проверка отсутствия внешних запросов текущей страницы
не заменяет эти проверки.
