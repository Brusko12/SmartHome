# Статус реализации

## Этап 1 — реализован

- Разделение frontend / API / services / repositories / persistence / adapters.
- React, TypeScript, Vite, Router, Tailwind, Lucide; действующая проверка API.
- FastAPI, SQLAlchemy, SQLite; типизированные настройки и `.env.example`.
- Все девять моделей, связи, индексы, внешние ключи и ограничения.
- Alembic: начальная миграция, повторный запуск с сохранением данных.
- Проверка здоровья backend и схемы БД, ошибки `503`.
- Backend-тесты, проверка TypeScript, сборка frontend, браузерная проверка.
- Документация разработки, архитектуры, схемы и фактического API.

## Этап 2 — реализован

- CRUD комнат и устройств через API, фильтры, пагинация, количество устройств.
- Шесть типов устройств, типизированные состояния, команды и параметры.
- VirtualDeviceAdapter без собственного хранилища; SQLite остаётся источником данных.
- Сохранение параметров и состояний, журналирование CRUD и команд.
- Атомарные изменения и события, откат при ошибке, защита от потери параллельных изменений.
- Перенос устройств при удалении комнаты без потери состояний.
- Контролируемый setup пользователя, дома и начальных комнат; PBKDF2-хеш пароля.
- Документация API и проверки этапа 2.

На этом этапе управление доступно через `/docs` и HTTP API. Страница React
пока показывает состояние системы. Полный интерфейс не реализован раньше этапа 3.

## Ещё не реализовано

| Этап ТЗ | Функциональность |
|---|---|
| 3 | Полный layout, навигация, главная панель и управление устройствами |
| 4 | Конструктор и исполнение сценариев, триггеры, условия, защита от циклов |
| 5 | Планировщик и симуляция, расчёт следующих запусков |
| 6 | Авторизация и сессии, история, настройки, backup/restore, диагностика |
| 7 | Раздача React через FastAPI, launcher, PyInstaller, Windows-дистрибутив |
| 8 | Полная проверка функций, офлайн-работы и чистого Windows |

Демонстрационные устройства и сценарии ещё не создаются. Настройка пользователя
пока доступна через контролируемую CLI-команду, без маршрутов входа и сессии.
Пароль хранится как PBKDF2-SHA256; авторизации изменяющих API пока нет.

Фоновая симуляция относится к этапу 5: температура термостата не меняется сама,
энергия розетки не накапливается, датчики сами не обновляются, движение пока
сбрасывается только командой `reset_motion`. Эти функции не заявляются готовыми.

Каталоги `launcher` и `scripts` содержат только описание будущих этапов.
`DeviceAdapter` — контракт; `VirtualDeviceAdapter` уже выполняет команды.
Это не готовое приложение управления домом и не готовый переносимый EXE.

## Пределы проверки

Текущая среда разработки — Linux. Локальные проверки не подтверждают запуск
Windows EXE. В CI предусмотрены backend-проверки на Linux и Windows; результат
конкретного CI-запуска нужно проверять отдельно. Тесты не заменяют итоговую
проверку дистрибутива на Windows без Python, Node.js и интернета.
